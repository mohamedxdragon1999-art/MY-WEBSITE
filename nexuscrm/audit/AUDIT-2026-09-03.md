## 1. Priority 1 — AI provider connections

### F17 · CRIT · SSE stream stall in all three readers

**Root cause.** Each `pull(controller)` does `const {value, done} = await reader.read()`
once, parses the lines, and `controller.enqueue()`s only when a chunk contains a content
delta. Per the WHATWG Streams spec a `pull()` that resolves **without enqueueing** is not
called again until the consumer reads and the queue is empty — but the queue is already
empty, so the source is simply never pulled again. Any non-content chunk that arrives in
its own packet (OpenAI's leading `role` delta, NIM's empty-content chunk, `finish_reason`,
`usage`, a gateway `: ping` comment, or a lone `[DONE]`) therefore freezes the stream.

- Frontend: `streamProviderDirect` — `NexusCRM_V4_Hardened.html` L1361–1445, `pull` at
  L1401; relay path `pull` at L1641. The 45 s abort (L1376) and the "watchdog" never fire
  because the fetch is still open — the UI shows a partial reply forever.
- Backend authenticated chat: `handleChatStream` `pull` at `backend/src/index.js` L2476 —
  completes only when the 15 s keepalive timer happens to enqueue `: ping` (measured:
  `done:true` at +15,007 ms).
- Public webchat: `publicWebchatMessage` `pull` at L10872 — no keepalive, so the visitor
  widget hangs for ever, and `saveReply()` (inside the never-re-invoked pull) never runs
  → **B11: AI replies are never written to `messages`** (inbox shows only the inbound
  line).

**Repro.**
```
node nexuscrm/audit/repro/stream_real3.mjs          # browser reader vs 9 real SSE shapes
node nexuscrm/audit/repro/backend_stream_timing.mjs # backend chat +15 s; webchat never
node nexuscrm/audit/repro/webchat_inbox.mjs         # AI reply never persisted
```
Result: shapes A–H (role-first, NIM, `: ping`, no-`[DONE]`, split `[DONE]`) **stall or
truncate**; only shape I (everything in one packet) completes. The existing tests pass
because `tests/test_backend.mjs` feeds the whole SSE body in one packet.

**Fix (validated in-memory, not applied):** loop inside `pull()` until something was
enqueued or the stream ended; treat `[DONE]` and `done` as close; keep parsing
`finish_reason`/`usage` but do not `return` on them.
```js
async pull(controller) {
  while (true) {
    const { value, done } = await reader.read();
    if (done) { flushTail(); controller.close(); return; }
    let enqueued = false;
    for (const line of splitLines(value)) {
      if (line === 'data: [DONE]') { flushTail(); controller.close(); return; }
      const delta = parseDelta(line);            // '' for role/finish/usage/ping
      if (delta) { controller.enqueue(delta); enqueued = true; }
    }
    if (enqueued) return;                        // spec will pull again
  }
}
```
`node nexuscrm/audit/repro/stream_fix_verify.mjs` applies this shape to the browser
reader in memory: A, C, D, E, G, H, I all complete with full text and `done:true`.
Move webchat's `saveReply()` out of `pull()` (run it on close/EOF via `waitUntil`).
**Regression test:** feed every shape with a per-chunk `await sleep(10)` (separate
packets) and assert full text + `done:true` within 2 s.

### N1 · CRIT · The Worker as committed cannot be deployed by either shipped path

`backend/src/index.js` L5–19 imports `./nx_compose.js`, `./nx_structured.js`,
`./nx_ast.js`, `./nx_validate.js`, `./nx_content.js`, `./nx_history.js`,
`./middleware/http.js`, `./security/crypto.js`, `./validators/input.js` (16 files, 1.4 MB
of app code reachable).

1. **Deploy Studio (in-app, "Deploy my backend now")** — `deployWorkerScript` (HTML
   L6361–6373) uploads one multipart part, `index.js`, whose content is exactly
   `GET /api/backend-source` = `backend/src/index.js` alone (server.js L350–357, HTML
   L6539). Cloudflare validates the module graph on upload → `No such module
   "nx_compose.js"` and the deploy fails. `tests/test_deploy_studio.mjs` L178 asserts
   `__moduleSource === BACKEND_SRC` (single file), i.e. the test pins the broken
   behaviour. All of this was introduced together in the single commit `29934f6`.
2. **`wrangler deploy` (auto-deploy.js / deploy.sh)** bundles with esbuild. The graph
   contains `backend/src/nx_structured.js` L12 `require('jsdom')` (literal string ⇒
   bundled) → jsdom → undici → Node built-ins: `fs`, `vm`, `net`, `tls`, `http2`,
   `child_process`, `worker_threads`, `zlib`… `backend/wrangler.toml` sets no
   `compatibility_flags = ["nodejs_compat"]`, so the bundle step fails on unresolved
   built-ins; even with the flag, `vm`/`net`/`child_process` are not real in workerd and
   jsdom+undici add ≈11 MB of unminified source (Free plan limit is 3 MB compressed).
   `parse5`, `css-tree`, `linkedom` are bundle-safe (no built-ins) but `parse5` and
   `css-tree` are **undeclared** (present only as jsdom transitive deps — `package.json`
   lists jsdom, playwright, sql.js, linkedom).

*Static analysis — I could not run wrangler in this sandbox (no outbound network).*
Verify with `cd nexuscrm/backend && npx wrangler deploy --dry-run --outdir /tmp/wb`.

**Fix.** (a) Replace the `require('jsdom')` in `nx_structured.js` with linkedom (already
used by `nx_validate`/`nx_repair`) or parse5; (b) declare `parse5` and `css-tree` in
`package.json`; (c) make Deploy Studio upload a **bundle** — either serve a pre-bundled
`dist/index.js` from `/api/backend-source` (build step: `esbuild backend/src/index.js
--bundle --format=esm --platform=browser`) or upload every module as its own multipart
part with correct relative names; (d) change `test_deploy_studio` to assert that the
uploaded module has **no unresolved relative imports** and that a `wrangler --dry-run`
bundle succeeds in CI.

### N4 · MED · `Retry-After` handled by sleeping inside the request (+ wasted final sleep)

`classifyHttpError` (index.js L1428–1435) turns a 429 into `retryAfterMs = min(RA,30) s`;
`callProvider` (L1555–1571) then `await sleep(raMs)` **after every failed attempt,
including the last one**. Measured with a stubbed 429 `Retry-After: 7`: the request
blocks **14,012 ms** and then returns 502. With two providers and RA = 30 the worst case
is 2 × 2 × 30 s = 120 s of a hung request; `realFetch` (HTML L2276) has no client
timeout, so the UI spinner just sits. Repro: `node nexuscrm/audit/repro/ai_conn_probe.mjs`
(last line). **Fix:** never sleep after the final attempt; cap in-request waiting at
~2 s and surface `retry_after` to the client; add an `AbortController` timeout in
`realFetch` for AI routes.

### N5 · MED · `/ai/models` ignores the custom NVIDIA base URL — key goes to the wrong host

`fetchLiveModels` (index.js L992, URL at L1009) always calls
`https://integrate.api.nvidia.com/v1/models` with `Authorization: Bearer <nvidia_key>`,
while `/ai/complete` and `/ai/health` honour `ai_nvidia_base_url`. A user who pointed the
NVIDIA provider at a private NIM (`https://nim.mycorp.example/v1`) gets the public
catalogue (models their NIM does not serve) and their private key is sent to NVIDIA's
public endpoint. Repro: `ai_conn_probe.mjs` step 1. **Fix:** derive the models URL from
the same base as chat; test asserting the outbound host.

### N3 · MED · Provider base-URL validation gaps (SSRF surface with the user's key attached)

`validProviderBaseUrl` (L1194–1210) blocks `localhost`, `0.0.0.0`, `[::1]`, `127/10/192.168/
169.254/172.16-31` by regex. Verified accepted at save time and then fetched by the Worker
with the user's bearer token, and the JSON `content` reflected to the caller
(`ai_conn_probe2.mjs`): `http://[::ffff:169.254.169.254]/v1` for NVIDIA;
`http://169.254.169.254/latest`, `http://metadata.google.internal/…` and any RFC1918
address for `custom` (because `allowLocalHost=true`). On Cloudflare's edge most private
ranges are blocked by the platform, but `wrangler dev`, a self-hosted workerd and the
Node relay in `server.js` are exposed, and `100.64/10` / `*.internal` are reachable
anywhere. **Fix:** parse IPv6 (`::ffff:` mapped, `::`), block CGNAT and `.internal`/
`.local`, and put the "custom may be local" allowance behind an explicit env flag.

## 2. Priority 1 — Website AI builder

### 2.1 Stored-XSS chain in generated / published sites

All of these end on `/s/:slug` (`publicSiteGet` L10504 and its duplicate at L11464),
which serves the stored HTML with **no `Content-Security-Policy`**, so any surviving
markup executes. The realistic attack path is: hostile site → `POST /ai/scan-site`
(plan extracted from *their* page) → `__pendingPlan` (HTML L7675 / `saveEditedPlan`
L13136 accepts arbitrary JSON) → `POST /sites {plan}` → published page. No admin
mistake is needed beyond "build a site from a competitor's URL".

**S8 · HIGH · JSON-LD escape is a no-op.** `generateSiteHtml` L7765:
`JSON.stringify(business).replace(/</g, '\u003c')` — in JS source `'\u003c'` **is** the
character `<`, so the replace substitutes `<` for `<` (`'a<b'.replace(/</g,'\u003c') ===
'a<b'`). The correct form, `'\\u003c'`, is used at L9586 (`enhanceSiteHtml`) and in the
HTML copy at L7987. Consequences: `plan.contact.phone/address/email`, `working_hours[]`,
`gallery_imgs[0]` and the site `name` land raw inside `<script type="application/ld+json">`.
jsdom execution proof (`node nexuscrm/audit/repro/xss_jsonld3.mjs`):
`</script><script>alert(document.domain)</script>`, `<img onerror=alert(1)>`,
`<svg onload=alert(2)>` via phone, address, working_hours and name **execute in every
design** (sentinel … template); the agentic-direction path is clean. (Payloads containing
`"` are neutralised by `JSON.stringify` — an earlier probe using quoted payloads was a
false negative; use quote-free payloads in the regression test.)
Fix: `'\\u003c'`, plus `\u2028/\u2029`; test: assert no literal `<` inside the ld+json
block and run the page in jsdom with `runScripts` and a sentinel `alert`.

**N2 · HIGH · Model-authored body HTML is not sanitised.** L7739–7740 strips only
`<style>` and `<script>` blocks. Everything else the model emits is published verbatim:
`onerror=`/`onclick=`/`onload=` handlers, `href="javascript:…"`, foreign `<iframe>`,
`<meta http-equiv="refresh">`, `<form action="https://evil…">`, `<object>/<embed>`
(`node nexuscrm/audit/repro/ai_body_xss.mjs` → 7/8 survive; `ai_body_xss2.mjs` → an
`onclick` handler from the "model" **executes** in jsdom on the sentinel design). The
prompt puts `OWNER INSTRUCTIONS (follow strictly): ${instructions}` and the plan's facts
straight into the model's context, so prompt injection from a scanned site or a
compromised proxy turns into stored XSS. This is exactly W-checklist item "AI HTML
sanitised like user HTML". Fix: a real allowlist sanitiser (parse5 is already in the
dependency graph and is bundle-safe): drop event attributes, `javascript:`/`data:`
URLs, `iframe/object/embed/meta/base/form[action≠self]`, and add a CSP on `/s/:slug`
(`default-src 'self'; script-src 'self' 'nonce-…' cdn.jsdelivr.net …` per what the
runtime scripts need).

**S3 · HIGH · User-supplied HTML stored verbatim.** `POST/PATCH /sites {html}` stores
`<script>` and anything else, served with no CSP (`site_probe.mjs` step 11). Same
sanitiser + CSP as above; the user's own rule says user HTML must be sanitised.

**S9 · HIGH · `webhook_url` string-replaced into JavaScript.** L7677 → L9261 (and
L10284): `fetch('__WEBHOOK_URL__')` is filled with the raw value; `');alert(15);//` closes
the string (`xss_plan_probe.mjs`: "webhook_url JS-string breakout: true"). Fix: validate
`https:` URL and embed with `JSON.stringify`.

**S10 · MED · `scene_text` breaks out of `<script>`.** `threeSceneScript` L8491+
embeds `String(window.NX_SCENE_TEXT||"…")` via `JSON.stringify` without `</`-escaping;
`</script><script>alert(16)</script>` is present verbatim for the text scene `sp17`.
Fix: `.replace(/<\//g,'<\\/')` after stringify.

**S11 · MED · URL fields are attribute-escaped but scheme-unvalidated.** `gallery_imgs`,
`hero_image`, `video_url` accept `javascript:` (all four normal designs: "onerror,
js_src, svg_onload" in `xss_plan_probe.mjs`). Allow `https:` (and `data:image/*` for
favicons only).

**S12 · HIGH · Template design renders plan text raw.** With `design_id:'template'`
(`__tpl()` L7496 + `NX_TEMPLATE_LIB` L6003) `about`, `hero_sub`, `cta_primary`,
`services[].icon` are inserted unescaped: raw `<script>`, `<iframe>`, `<meta refresh>`,
`onmouseover`, `javascript:` links all reach the published page. Route the template
fill through the same `__be()` escaping that `renderSectionsHtml` L2800 uses (that path
is verified clean).

Verified **safe** (no finding): `custom_css`, `favicon`, `spline_url`, `<title>`,
og/meta attributes, canonical, `nxVisualApplyEdits` text edits, all normal body slots
(`xss_where3.mjs`).

### 2.2 Data integrity, publishing and tenancy

**S2 · HIGH · IDOR.** L10330 `DELETE /sites/:id/snapshots` deletes by `site_id` only.

should ignore `published` on regenerate unless explicit.

**F19 · MED · `autoOptimizePreview` (HTML L12455)** PATCHes the iframe's live DOM back

**F7 / F15 / F8 / F14 · MED · Fake local success.** `buildSiteWithAI` L7676–7684 catches

**F18 · MED · Preview iframes.** `ds-frame` L12514 uses `sandbox="allow-same-origin
allow-scripts"` on untrusted generated HTML — with both flags together the sandbox is

shares the app origin, i.e. `localStorage nx_token`). `ve-frame` L12605 is
`allow-same-origin` only (no scripts — acceptable) but the visual editor reads/writes
its DOM directly, which is how F19 re-stores unsanitised markup. Drop
`allow-same-origin` on `ds-frame` and talk to frames via `postMessage`.

**F16 / T1 · HIGH · Identity leak in the template design.** `design_id:'template'` is
offered by `/ai/site-designs`; without a plan the generated page and its embedded chat

R C Atkin phone, e-mail, owner name, postal address, alt texts and a drainage knowledge
base (`template_pii4.mjs`). Any customer choosing that design ships someone else's
business data. Fix: strip identity from the library (placeholders only), gate the design
behind an explicit plan, add a leak test that greps the output for the known strings.

`localtest.me`; and any public host may 302 to an internal one. This is W-checklist
"SSRF incl. DNS rebinding + 169.254.169.254". Fix: `redirect:'manual'` + re-check every
hop, IPv6 parsing, block CGNAT/`.internal`/`.local`, allow only ports 80/443, cap body
size, and don't cache failures/blocked results.

### N8 · HIGH (new) · Every regenerate/settings save silently disconnects the contact form — leads are lost

`SITE_JS` L9261 posts the contact form to `fetch('__WEBHOOK_URL__')`. The wizard fills
it with the workspace's public webhook (HTML L7670, L12740). But `saveSiteSettings`
(L12896), `doRegenerateSite` (L12962) and `duplicateSite` (L12932) send **no
`webhook_url`**, and the backend regenerate path (L10282–10286) only patches the URL
when the body provides one — nothing is remembered in `site_meta` (no such column).
Result, proven by `node nexuscrm/audit/repro/lead_loss_after_regenerate.mjs`:

```
1. created via wizard            → form posts to workspace webhook ✓ | visitor submit → 200
2. after Site Settings save      → form posts to ""                  | visitor submit → 401
3. after "Regenerate with AI"    → form posts to ""                  | visitor submit → 401
contacts before/after the 3 visitor submissions: 1 → 1
```
An empty URL makes the browser POST to the page itself (`/s/:slug`), which the router
answers with **401 "Unauthorized — please sign in again."** — the visitor sees
"Could not send", the owner never sees the lead, and nothing is logged. Because
`saveSiteSettings` is also the only way to change fonts/colours, practically every
customised site is in state 2 or 3. Combined with N7 (`published:true` forced), the
broken form is live immediately.

Fix: the backend must derive the webhook itself from `w.public_token` + request origin
at render time (never trust/require the client to send it), persist the origin in
`site_meta`, and make `/s/:slug` answer a `POST` with a JSON 405 that says what happened.
Regression test: build → PATCH settings → submit form → assert a new contact exists.
